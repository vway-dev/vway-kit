# 프로젝트 하네스

## `/harness-init`

```text
/harness-init        # 인자 없음 — 대화형 마법사, 직접 호출
```

프로젝트에 맞는 `CLAUDE.md`·규칙·기술 문서를 만듭니다. 게이트를 거는 `/vdev-init` 과는 독립입니다.

1. **감지** — 의존성 파일(`package.json`·`pyproject.toml`·`go.mod` 등)과 디렉터리로 언어·프레임워크 판별.
2. **리서치** — 최신 컨벤션·무료 기성 솔루션을 웹에서 조사하고, 기존 코드의 실제 컨벤션도 분석합니다.
   버전은 구성요소별 최신이 아니라 **함께 기동되는 호환 집합**으로 고르고 근거를 호환성 매트릭스로 남깁니다.
3. **생성** — `CLAUDE.md`·규칙·기술 문서(SRS·SDS·코드 스타일·온보딩·운영 cross-cutting 컨벤션)를
   분류별 폴더로. 기본은 **`.md` 만** 만듭니다.
4. **검증** — 품질·문서 간 일관성·런타임 조합 호환·다중 컴포넌트 통합 정합을 점검합니다.
5. **미리보기 후 확정** — 확정해야 파일을 씁니다. 이후 임시 리서치 사본을 정리합니다.

- **덮어쓰기 없음** — 기존 파일은 관리 블록 단위로만 갱신하고 충돌은 보고합니다.
- 보안 스캐너·CI·폴더 생성·버전 고정 같은 실제 설정은 **항목별 동의**가 있을 때만 적용합니다.
- 슬래시 커맨드는 생성하지 않습니다.
- 생성 규율의 SSOT 는 룰 [`harness-rules`](../../rules/harness-rules.md).

## `/wiki-init`

```text
/wiki-init   # 인자 없음 — 대화형, 직접 호출
```

기존 문서를 한 파일 한 개념의 노드(YAML front matter)로 이관하고 `docs/graph/graph.yaml` 을 만듭니다.
임베딩은 쓰지 않습니다 — 관계는 손으로 쓰는 front matter 이고 그래프는 그것을 읽을 뿐입니다.
`wiki_id` 가 있는 문서는 다시 제안되지 않습니다(멱등).

- **유지** — `doc-sync` 가 노드의 `sources` 마커(워킹트리 blob hash — squash/rebase 가 가짜 stale 을
  못 만듦)와 그래프를 맞추고, `wiki` 게이트가 커밋마다 읽기 전용으로 검증합니다([등급과 게이트](tiers-and-gates.md#게이트별-동작)).
- **읽기 경로** — `/vdev` 의 Dev 트랙은 바꿀 파일을 노드로 매핑(`wiki_graph.py --nodes-for <경로들>`)하고
  그 이웃(`--neighbors <id>`)을 작업 컨텍스트로 읽는 데서 시작합니다.
- **CI** — 마지막 단계에서 `wiki-verify.yml` 을 제안합니다([CI 워크플로](ci-workflows.md)).
- 설정은 `vdev-config.wiki`(`root`·`index`·`max_lines` 등).

## `harness-insight`

지정 기간의 Claude Code 활동을 집계해 반복 지시·핫스팟을 **하네스 후보**로 뽑고, 누적된 프로젝트
메모리를 정리합니다. "지난 7일 인사이트", "메모리 정리해줘" 같은 요청으로 부릅니다.

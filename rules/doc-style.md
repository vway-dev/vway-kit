# Doc Style Rules

> 적용: 모든 산문 — `.md`·룰·주석·독스트링·에이전트 지시문·커밋 본문·ALM 항목 제목·본문·코멘트.
> 제외: 코드 블록·명령어·에러 문자열·외부 스펙 인용(원문 유지).

## 문체

1. **개조식.** 서술형 종결(`~한다`·`~된다`·`~이다`·`~았다`·`~않는다`) 금지 → 명사형(`~함`·`~됨`·`금지`·`필요`·`없음`)으로 끝냄. 영문 산문은 동등하게 짧은 명사구·명령형.
   예외: 사용자에게 말을 거는 매뉴얼(README·USAGE 류)의 합쇼체 — 독자가 사람이라 어투가 내용의 일부.
2. **한 항목 한 사실.** 사실이 둘이면 항목도 둘.
3. **군더더기 제거.** 자명한 주어·"~하는 것이다" 류 완곡·중복 수식.
4. **압축 대상은 문장이지 내용 아님.** 근거(왜)·계약·함정·실측치는 유지 — 짧게.

## 금지

5. **변경 이력·마이그레이션 노트·"이전엔 X"** — 커밋이 맡음([commit-discipline.md](commit-discipline.md)).
6. **구현 계획 잔재** — 단계 목차·체크박스·"다음 단계"·TODO. 계획은 `docs/` 의 플랜 문서 몫.
7. **장식 구조** — 내용이 요구하지 않는 목차·중첩 섹션 뼈대·구분선·이모지·표.
8. **되풀이** — 다음 줄·코드·시그니처가 이미 말하는 것.

## 배치

9. **한 사실 한 곳.** 나머지는 링크. 복제 발견 시 SSOT 하나 남기고 삭제.
   예외: ALM 항목 본문 — 저장소 밖 독자에게 링크는 읽을 수 없는 문장이라 중복 허용
   ([item-body](../skills/task-import/references/item-body.md) 「자기완결」).
10. **`CLAUDE.md` = 공통 규칙만** — 빌드 명령·레이아웃·불변식·SSOT 링크. 절차·근거 서술은 해당 SSOT 에.
11. **파일 역할·설계 근거는 소스 헤더 독스트링이 SSOT** — `.md` 로 복제 금지.

## 대조

두 도구가 축을 나눠 가짐 — **어떻게 썼는가**(문체)와 **쓰기 전후로 같은 사실이 남았는가**(손실).

12. **문체 검사**: `python3 .claude/vway-kit/scripts/doc_style_check.py --lint <경로...>` —
    위 규칙 중 기계가 판정하는 절반. 나머지(9~11 · "근거는 유지")는 `prose-review` 몫.
    범위는 `vdev-config.doc_style.paths`/`exclude` — 기본은 `.md`·`.py`·`.sh`·`.bash`,
    `exclude` 기본은 재생성되는 모든 `CHANGELOG.md` 와 `docs/superpowers/`·`.superpowers/` 트리.
    GitHub 이슈·PR 템플릿은 설정과 무관하게 늘 빠짐(체크리스트가 곧 양식).
    블록이 없거나 `enable: false` 면 아무것도 안 검사.
13. **재작성 후 손실 확인**: `python3 .claude/vway-kit/scripts/doc_invariants.py --changed` —
    링크·헤딩·코드펜스·front matter 키·코드 스팬이 줄었는지 HEAD 와 대조. 게이트가 아니라 판단 재료.

| 코드 | 무엇 | 대신 |
|------|------|------|
| `HIST` | 변경 이력 서술(규칙 5) — `previously`·`used to`·`이전에는`·`바뀌었` | 지금 힘을 가진 사실 |
| `SHA` | 산문 속 커밋 sha | 규칙을 이름으로 부름 |
| `PLAN` | 플랜·스펙 문서 포인터, 체크박스 항목(규칙 6) | 사실 자체 |
| `FILLER` | `just`·`simply`·`actually`·`However,`·`in order to`(규칙 3) | 삭제 |
| `ENDING` | 한글 서술형 종결(규칙 1) | 명사형 |
| `ANCHOR` | 파일명 뒤에 붙은 줄 번호 | 파일명만 |
| `META` | 변경 필드: `@author`·`Author:`·`Last updated:`·`작성자` | 없음 — git 이 쥠 |
| `TRAP` | `Trigger:` 나 `Symptom:` 이 빠진 `CRITICAL TRAP:` 박스 | 세 줄 전부, 아니면 박스를 안 씀 |

경고만: `LONG` 은 산문 한 줄 100자 초과(표 제외), `CLAIM` 은 헤지된 크기(`approximately`·
`roughly`·`대략`·숫자 앞의 `약`·`30% faster`·`2x cheaper`·`2배 빠름` — 맨 숫자는 안 읽음).
`ENDING` 은 규칙 1 의 예외를 그대로 구현 — 합쇼체(`~니다`)와 조사(`~마다`·`~보다`)는 위반
아님, `아니다` 는 종결이라 잡힘.

## 주석은 마지막 수단

14. **어떻게는 적지 않음.** 어떻게는 코드가 말함.
15. **대신 코드가 터지게 할 것.** 독자가 어길 수 있는 제약은 문장이 아니라 검사 —
    `assert`·예외·검증된 경계·타입.
16. **터질 자리가 없을 때만 박스.** 발화할 런타임 순간이 없는 함정만 이 모양을 얻음:

    ```
    # CRITICAL TRAP: <무엇이, 조용히 깨지는가>
    # Trigger: <거기 닿는 조건>
    # Symptom: <닿았을 때 독자가 보는 것>
    ```

    세 줄은 **붙어 있어야 함** — 사이에 빈 줄도 빈 주석(`#`)도 금지(검사기가 끊기지 않은 런으로
    읽음). 독스트링 안에서도 본문 안에 세 줄을 함께 둠. 키 셋은 리터럴, 키 뒤는 프로젝트 주석
    언어.
17. **변경 이력·날짜·이름 금지.** 셋 다 git 이 쥠.
18. **줄 번호가 아니라 파일명.** 줄 번호는 다음 편집에 거짓이 됨.
19. **자명한 것 금지.** 자기 식별자를 되풀이하는 주석은 잡음.

남는 것은 근거이거나 제약이고, 한 줄에 들어감.

## 숫자는 측정이거나 계약

숫자는 **묶인 값**(타임아웃·상한·스키마 경계·프로토콜 상수)이거나 **잰 수치**를 낸 조건과
함께(`reps 3 에서 0.76 (n=15)`)일 때만. 조건을 같은 줄에 실으면 `CLAIM` 도 침묵함 — 무엇이
조건으로 세어지는지는 검사기의 `SILENCED_BY_ITS_CONDITIONS`. 나머지는 방향(`더 빠름`·`유계`).
인라인 코드 스팬은 줄을 넘기지 말 것 — 린트가 한 줄씩 읽어 걸친 스팬이 뒤 산문을 가림.

**두 레이어**: 커밋 게이트(`doc-style`)는 커밋이 바꾸는 파일만 보고 **경고만** 함. 판정은
트리 전체를 보는 CI(`doc-style.yml`) 몫.

# requirement 보드 전량 열거

[`alm-docs`](../SKILL.md) 2단계가 `general-purpose` 에이전트에 들려 보내는 지시.
보드 **하나**가 한 에이전트 몫 — 스페이스가 둘이면 dispatch 가 둘을 따로 띄움.
**읽기 전용** — 판정 재료만 생산하고, 대조도 쓰기도 부른 쪽 몫.

## 입력 (dispatch 가 채워서 넘김)

- **도구 접두** — 아래 도구 이름은 전부 그 접두 뒤에 붙음(`<접두>list_workboard_items`).
  dispatch 가 해석해 넘긴 값만 사용, **이름 조립 금지**
- 열거할 **보드 id**
- 그 보드가 속한 **스페이스 키**
- **출력 경로**

## 절차

1. `list_workboard_items(workboardId=<보드 id>, sort: "created", limit: 30)`.
   처음부터 좁혀 호출 — 도구 설명 자신이 큰 보드는 응답 크기로 실패한다고 경고함.
2. 다음 페이지는 직전 페이지에서 **가장 오래된** 항목의 생성 시각을 `createdBefore` 로
   넣어 반복.
3. `createdBefore` 는 **그 시각 포함** — 커서로 쓴 항목이 매 페이지 되돌아옴. 항목 id 로
   중복 제거하고, 총계도 중복 제거 후의 수.
4. **끝 판정은 반환 개수 < `limit`**(또는 직전 페이지 밖 새 항목 0건). "더 안 나오면 끝" 은
   3번 때문에 영원히 거짓이라 종료 조건으로 사용 금지.
5. 본문은 펼치지 않음 — 이 경로가 대조하는 것은 **제목 한 줄**뿐이고, 전량을 펼치면 응답
   크기에 걸려 열거가 중간에 죽음. 그 중간까지가 "전량" 으로 보고되는 것이 이 단계의
   가장 비싼 실패.

## 금지

- `create_*`·`update_*`·`delete_*`·`create_entity_link` 호출 금지 — 읽기만 함
- 지정된 출력 경로 밖 어디에도 쓰지 않음
- 도구 이름을 조립하지 않음 — 넘겨받은 접두만 씀
- 수치를 지어내지 않음 — `pages`·`mcp_calls` 는 실제로 센 값

## 출력

지정된 경로에 JSON 하나:

```json
{"space": "dev3",
 "board": "<보드 id>",
 "items": [{"id": "REQ-118", "title": "카드 결제 지원"}],
 "meta": {"pages": 3, "mcp_calls": 4, "truncated": false}}
```

`truncated` 는 **보드 끝까지 도달하지 못했는가**. 응답 크기나 페이지 상한으로 끊겼으면
`true`. 이 값이 항목 목록보다 중요함 — 잘린 열거의 0건은 완전한 열거의 0건과 다른 답이고,
부른 쪽은 `true` 를 보면 「보드에만 있음」과 「끊긴 매핑」을 아예 세지 않음.

## 반환

표 한 줄 — 출력 경로 · 항목 수 · 페이지 수 · MCP 호출 수 · 잘림 여부. **본문은 응답에
싣지 않음**: 요약이 숫자를 조용히 바꾸면 부른 쪽이 못 알아봄.

# 기능 설계 조사

[`alm-trace`](../SKILL.md) §5-1 과 [`task-sync`](../../task-sync/SKILL.md) R5b 가 `general-purpose`
에이전트에 들려 보내는 지시. 기능 **하나**가 한 에이전트 몫.
**읽기 전용** — 설계 본문 초안만 돌려주고, 항목 생성·수정은 부른 쪽 몫.

## 입력 (dispatch 가 채워서 넘김)

- **기능 이름**과 **모듈 이름** — 보드의 feature·module 라벨 값 또는 제목 `[모듈] 기능명`
- **설계 템플릿 경로** — 절 이름과 순서를 그 파일에서 가져옴
- **호스트 저장소 루트**
- 있으면 **현재 설계 본문** — 부른 쪽이 읽은 항목 본문. 없으면 빈 값

## 절차

1. 설계 템플릿을 읽어 절 목록을 정함.
2. 호스트 설계 문서를 먼저 읽음 — `docs/sds/README.md` 와 그 기능을 다루는 `docs/sds/` 파일,
   요구 문서 `docs/srs/` 에서 그 기능의 요구와 수용 기준. 없으면 건너뜀.
3. 코드에서 그 기능의 현재 모습을 확인함 — 화면(컴포넌트·입력 검증) · 처리 흐름(진입점부터
   외부 연동까지) · 데이터(스키마·마이그레이션·ORM 모델). 문서와 코드가 다르면 코드가 현재 모습이고,
   그 차이를 「결정과 근거」에 한 줄 적음.
4. 템플릿 절마다 채움. 기능의 **현재 모습 전체**가 대상이고 이번 변경만이 아님.
   - 비즈니스 로직 절의 처리 흐름은 mermaid `sequenceDiagram` 코드블록.
   - 레이어가 없는 기능은 그 절에 "해당 없음".
5. 현재 설계 본문이 있으면 사람이 적은 결정·근거 문장은 보존하고, 코드와 어긋나는 서술만 고침.

## 작성 규칙

[`task-import/references/item-body.md`](../../task-import/references/item-body.md) — 설계 본문은 개발자
독자지만 저장소 없이 읽혀야 함. 파일 경로는 설명 뒤의 보조 정보로만.

## 금지

`create_*`·`update_*`·`delete_*`·`create_entity_link` 호출과 파일 쓰기 금지.

## 출력

- 설계 본문 마크다운 전체(템플릿 절 순서 그대로).
- 본문 뒤 `---` 아래에 근거 목록 — 절마다 읽은 문서·코드 경로 한 줄씩. 부른 쪽이 보고에만 쓰고
  본문에는 안 올림.

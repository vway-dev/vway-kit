# 보드 전량 유사 스캔

[`alm-trace`](../SKILL.md) 4단계가 `general-purpose` 에이전트에 들려 보내는 지시.
보드 **하나**가 한 에이전트 몫 — 요구사항 보드와 작업 보드를 함께 볼 때도 지시는 이것
하나이고, dispatch 가 보드마다 따로 띄움.
**읽기 전용** — 판단 재료만 생산, 중복 여부 결정과 항목 생성은 부른 쪽 몫.

## 입력 (dispatch 가 채워서 넘김)

- 유사한 것을 찾을 **요청 텍스트**
- **도구 접두** — 아래 도구 이름은 전부 그 접두 뒤에 붙는다(`<접두>list_workboard_items`).
  dispatch 가 해석해 넘긴 값만 사용, 이름 조립 금지
- 스캔할 **보드 id**
- 그 보드가 담는 것 — **요구사항** · **작업** · **기능 설계** 중 하나. 유사 근거를 무엇에 대고
  재는지가 이 값으로 갈림: 요구사항 보드에서는 *같은 것을 요구하는가*, 작업 보드에서는
  *같은 것을 건드리는 작업인가*, 기능 설계 보드에서는 *같은 기능을 설계하는가*. 뒤바꿔 재면
  이미 구현된 기능의 결함이 신규 요구로 올라감.

## 절차

1. `list_workboard_items(workboardId=<보드 id>, sort: "created", limit: 30)`.
   처음부터 좁혀 호출 — 도구 설명 자신이 큰 보드는 응답 크기로 실패한다고 경고.
2. 다음 페이지는 직전 페이지에서 **가장 오래된** 항목의 생성 시각을 `createdBefore` 로
   넣어 반복.
3. `createdBefore` 는 **그 시각 포함** — 커서로 쓴 항목이 매 페이지 되돌아옴. 항목 id 로
   중복 제거하고, 총계도 중복 제거 후의 수.
4. **끝 판정은 반환 개수 < `limit`**(또는 직전 페이지 밖 새 항목 0건). "더 안 나오면 끝" 은
   3번 때문에 영원히 거짓이라 종료 조건으로 사용 금지 — 그 조건을 믿으면 임의 지점에서
   끊고 "끝까지 도달" 로 적게 됨.
5. 제목만으로 판단이 서지 않는 후보에 한해 `get_workboard_item` 으로 본문을 펼침.
   전량을 펼치면 응답 크기에 걸려 스캔이 중간에 죽고, 그 중간까지가 "전량"으로 보고됨.

## 금지

`create_*`·`update_*`·`delete_*`·`create_entity_link` 호출 금지.

근거를 한 줄로 못 대는 후보는 제외. 사람이 확인할 수 없는 후보는 목록만
길게 만들고, 긴 목록은 실제 중복을 눈에서 가림.

## 출력

| itemKey | id | 제목 | 유사 근거 | 등급 |
|---|---|---|---|---|
| CRS-0031 | … | 알림 수신 동의 관리 | 수신 동의 상태를 사용자별로 저장하는 같은 요구 | high |

등급은 `high`·`medium`·`low`. 후보가 없으면 표는 비움.

**등급은 부르는 쪽의 행동을 정함** — 셋이 서로 다른 일을 시킴:

| 등급 | 뜻 | 부른 쪽이 하는 일 |
|---|---|---|
| `high` | 같은 대상을 가리킨다고 **한 줄로 단정** 가능. 제목이 비슷한 정도가 아니라 본문이 같은 기능·화면·규칙을 말함 | 묻지 않고 연결 |
| `medium` | 관련은 있으나 같은 것인지 단정 못 함. 겹치는 범위가 일부이거나 본문이 얇음 | 사람에게 물어 고른 것만 연결 |
| `low` | 같은 영역을 스칠 뿐 | 연결 안 함. 이름만 보고에 남음 |

확신이 안 서면 `medium`. `high` 는 확인 없이 링크가 그어지므로, 후하게 매긴 하나가
엉뚱한 요구사항에 결함을 매달아 두고 아무도 그 사실을 안 봄. 반대로 `low` 를 남발하면
사람이 볼 기회 없이 후보가 사라지므로, 근거를 댈 수 있으면 `medium`.

이어서 **스캔 실적** 세 값을 반드시 함께 냄:

- 훑은 항목 총 N건
- 페이지 호출 M회
- **보드 끝까지 도달했는가** — 아니면 마지막으로 본 생성 시각까지 함께

세 번째 값이 후보 표보다 중요함. 응답 크기나 페이지 상한으로 끊긴 스캔을 "없음"으로
읽으면 이미 있는 요구사항이 한 번 더 만들어지고, 그 뒤로 그래프가 두 갈래로 갈라져
`derives`·`verifies` 를 따라 올라가는 전파가 어느 쪽도 온전히 못 닫음.
**후보가 0건이어도 도달 여부는 기재** — 0건이야말로 이 값 없이는 못 읽는 결과.

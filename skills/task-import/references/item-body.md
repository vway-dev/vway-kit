# ALM 항목 본문

ALM(Recoble·Teamer) 항목에 올라가는 본문의 규칙. [alm-trace](../../alm-trace/SKILL.md) ·
[task-sync](../../task-sync/SKILL.md) · [alm-docs](../../alm-docs/SKILL.md) ·
[integration](../../integration/SKILL.md)(회차) 가 본문을 쓸 때 따름.
제목 형식은 [recoble-status](recoble-status.md) 「항목 제목」.

## 독자

주로 읽는 사람은 비개발자이고, 저장소에 접근할 수 있는 사람은 한정됨.

| 본문 | 독자 |
|---|---|
| 설계 계층 — `feature_design` 계층, 없으면 `marker` 계층의 `derives_from` 이 가리키는 계층 | 개발자 |
| 작업 계층(`marker`) | 개발자 |
| handoff summary 의 `Implementation` 절 | 개발자 |
| 그 밖의 계층(요구사항·검증·결함·회차) · summary 의 `Verification`·`Notes` 절 · 그 밖의 handoff 종류 | 비개발자 |

## 비개발자 본문

- 쓰지 않는 것: 코드 식별자(함수·클래스·변수·필드 key) · 파일 경로 · 커밋 sha · 브랜치 이름 ·
  스크립트·내부 도구 이름 · 풀어 쓰지 않은 약어.
- 기술 개념은 사용자나 업무가 관찰하는 말로 풀어 씀 — "`OrderService` 재시도 추가" 가 아니라
  "결제가 잠깐 실패하면 자동으로 한 번 더 시도함".
- 도메인 용어는 저장소 SRS 용어집이 있으면 그 이름 그대로. 한 대상을 두 이름으로 부르면 두 기능으로 읽힘.
- 빌드는 버전 이름(릴리스 태그 등)으로. 버전 이름이 없으면 날짜와 환경으로 특정.
- 절차는 사람이 따라 할 수 있는 화면 조작 순서로 — 명령어·테스트 파일 이름 대신 무엇을 눌러 무엇을 봤는지.

## 자기완결

- 저장소 문서·파일을 근거로 링크하지 않음. 그 문서에서 필요한 내용을 본문에 짧게 풀어 씀.
- [doc-style](../../../rules/doc-style.md) 9번(한 사실 한 곳, 나머지는 링크)은 ALM 본문에 적용 안 함 —
  저장소 밖 독자에게 링크는 읽을 수 없는 문장이라, 중복이 정보 없음보다 나음.
- 개발자 본문도 같음. 경로는 설명 뒤의 보조 정보로만 두고, 경로만 남기고 설명을 생략하지 않음.
- 설계 본문은 저장소 설계 문서의 그 기능 부분을 중복이어도 담음. 구조는 그 계층의 `template` 절을 따름.

## 형식

- `templates/alm/*`·`templates/handoff/*` 골격을 채운 마크다운이 그대로 감. MCP 도구 스키마 설명은 HTML 을
  권하지만 마크다운도 받음 — 변환하지 않음. 변환은 부모가 본문을 다시 쓰는 일이라 값이 안 맞음.
- 템플릿의 `{…}` 는 채울 자리이고 `<!-- … -->` 주석은 작성 지시 — 둘 다 본문에 그대로 옮기지 않음.

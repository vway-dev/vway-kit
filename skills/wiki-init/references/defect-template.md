# Defect 문서 템플릿

defect 기록은 일기가 아니라 실패 사례 데이터베이스의 한 행. 프롬프트 수정·새 규칙·회귀
테스트를 먹여 살리려 존재. 아래 블록을 복사해 모든 절을 채우고, 주석 처리된 필드는
채우거나 **지울 것** — 그대로 남긴 자리표시자는 "선택 사항"이 아니라, 누군가 그 줄을 지울
때까지 모든 커밋을 막는 검증 실패.

sha 는 전부 따옴표. 없으면 `0123456` 은 YAML 1.1 8진수라 숫자 42798.

```markdown
---
wiki_id: defect.<slug>
title: <한 줄 — 무엇이 깨졌나>
tags: [<area>]
affects: [<이 문서가 깨뜨리는 문서의 wiki id>]
# 선택 — 해당하는 것만 주석을 풀고 나머지는 줄째로 지운다.
# commit: "<이것을 들여온 커밋의 sha>"
# regression_test: <path::test_name>
# promoted_to_rule: <rules/*.md — 실제로 승격한 뒤에만>
---

## Input
무엇이 들어갔나 — 요청, 페이로드, 상태.

## Output
무엇이 나왔고, 무엇이 나왔어야 했나.

## Defect
관측된 실패. 정확한 에러 인용.

## Root Cause
왜 일어났나. 증상보다 한 단계 아래.

## Fix
무엇을 바꿨고, 왜 그것이 증상이 아니라 원인을 닫는가.
```

`used_by` 와 `defects` 는 생성 필드 — 손으로 쓰기 금지.
Rule 승격은 사람의 판단: 임계값은 경고만 띄움.
